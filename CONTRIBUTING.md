# 🤝 Contributing

Thank you for your interest in contributing to **InstaReport**!

Please read this guide carefully before contributing, along with our [Code of Conduct](CODE_OF_CONDUCT.md).

---

## Important Note on the Codebase

The InstaReport codebase is **proprietary and distributed exclusively through official, license-protected channels**. The public GitHub repository serves as the **official documentation, branding and release home** for the project.

As a result, contribution opportunities in this repository focus on:

- 📝 **Documentation** — improving guides, FAQ, troubleshooting and references.
- 🐛 **Issue reporting** — well-documented bug reports.
- 💡 **Feature requests** — clear, detailed proposals for the roadmap.
- 🌐 **Localization** — translating report reasons and UI text.
- 🔍 **Security research** — responsible vulnerability reporting (see [SECURITY.md](SECURITY.md)).

---

## Ways to Contribute

### 1. Report a Bug

Bugs should be reported using the [Bug Report template](.github/ISSUE_TEMPLATE/bug_report.yml). Include:

- Your platform (Windows / Linux / Termux / Telegram bot).
- Your version.
- Steps to reproduce.
- Expected vs. actual behaviour.
- Error messages or screenshots if available.

### 2. Request a Feature

Use the [Feature Request template](.github/ISSUE_TEMPLATE/feature_request.yml). Explain:

- The problem the feature solves.
- How you envision it working.
- Which platform(s) it should support.

### 3. Improve Documentation

Documentation contributions are welcome. Please follow the existing structure:

- Keep language clear, factual and consistent.
- Never invent or exaggerate features — only document what is truthful.
- Match the style and tone of existing pages.

### 4. Report Security Issues

**Do not open a public issue** for security vulnerabilities. Follow the private reporting process in [SECURITY.md](SECURITY.md).

---

## Contribution Guidelines

- Be respectful and constructive — follow our [Code of Conduct](CODE_OF_CONDUCT.md).
- Search for existing issues before creating a new one.
- Provide complete, accurate information.
- Do not ask for license keys, paid access or unofficial copies in issues.

---

## Review Process

- Issues are triaged and labelled by the maintainers.
- Bug reports are prioritized by severity and impact.
- Feature requests are added to the [roadmap](ROADMAP.md) when approved.
- Documentation PRs are reviewed for accuracy and style.
